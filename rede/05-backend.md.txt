# CDN 加速控制面板 — 后端设计

> 版本：v0.1
> 框架：NestJS + TypeScript
> ORM：Prisma
> 数据库：MySQL 8
> 缓存/队列：Redis + BullMQ

---

## 1. 技术选型

### 1.1 核心依赖

| 类别 | 选型 | 说明 |
|------|------|------|
| 框架 | NestJS 10 | 模块化、依赖注入 |
| 语言 | TypeScript 5 | 严格模式 |
| ORM | Prisma 5 | 类型安全 |
| 数据库 | MySQL 8 | 主数据 |
| 缓存 | Redis 7 | 会话、缓存、队列 |
| 队列 | BullMQ | 异步任务 |
| 认证 | @nestjs/jwt + passport | JWT |
| 校验 | class-validator + class-transformer | DTO 校验 |
| 文档 | @nestjs/swagger | API 文档 |
| 实时 | @nestjs/websockets + socket.io | WebSocket |
| 定时 | @nestjs/schedule | Cron |
| HTTP | @nestjs/axios | 调外部 API |
| 日志 | winston + nest-winston | 结构化日志 |
| 加密 | bcrypt + crypto | 密码、密钥 |
| 邮件 | nodemailer | 邮件 |
| 短信 | 阿里云/腾讯云 SDK | 短信 |
| 验证码 | svg-captcha | 图形验证码 |
| 限流 | @nestjs/throttler | 接口限流 |
| 队列面板 | @bull-board/nestjs | 队列监控 |

### 1.2 开发依赖

| 类别 | 选型 |
|------|------|
| 包管理 | pnpm |
| Monorepo | pnpm workspace |
| 类型检查 | tsc |
| 测试 | Jest + Supertest |
| 代码规范 | ESLint + Prettier |
| Git Hook | husky + lint-staged |
| 提交规范 | commitlint |

## 4. 认证与鉴权

### 4.1 JWT 策略

**Access Token：**
- 有效期：2 小时
- 载荷：`{ sub: userId, username, roleType, permissions }`
- 签名：HS256

**Refresh Token：**
- 有效期：7 天
- 存 Redis：`refresh:{userId}:{jti}`
- 刷新时轮换

**JWT Payload：**
```ts
interface JwtPayload {
  sub: number
  username: string
  roleType: number
  permissions: string[]
  iat: number
  exp: number
}
```

4.2 守卫链

```
@UseGuards(JwtAuthGuard, RolesGuard, PermissionsGuard)
```

JwtAuthGuard：

· 校验 Token
· 注入 req.user

RolesGuard：

· 校验 @Roles('admin')

PermissionsGuard：

· 校验 @RequirePermissions('domain:create')

4.3 装饰器

```ts
@Public()                          // 免认证
@Roles('admin', 'super_admin')     // 角色
@RequirePermissions('domain:create') // 权限
@CurrentUser() user: User          // 当前用户
```

4.4 数据范围

· 用户端接口：where: { userId: currentUser.id }
· 管理员端接口：可指定 userId 查询全部
· 用 DataScopeGuard 或 Service 层手动控制

4.5 节点 Token 鉴权

NodeTokenGuard：

· 读 Header X-Node-Id、X-Node-Token、X-Timestamp、X-Signature
· 查 node_tokens 表验证 token
· 校验时间戳（±300s）
· 校验 HMAC 签名
· 防重放：Redis 存 signature，5 分钟过期

4.6 对外 API 签名

SignatureGuard：

· 读 Header X-Access-Key、X-Timestamp、X-Signature
· 查 user_api_keys 表
· 按规则拼 stringToSign
· HMAC-SHA256 校验
· 限流：Redis 计数

5. 核心业务流程

5.1 用户添加域名

```
1. 用户提交域名 + 源站信息
2. DomainService.create()
   ├── 校验域名格式、唯一性
   ├── 查用户当前套餐
   ├── 校验配额（域名数、流量）
   ├── 根据套餐 accessType 决定接入模式
   │   ├── 自建：分配 nodeGroupId，生成 CNAME
   │   └── 厂商：调 vendor driver 创建域名
   ├── 写 domains 表
   ├── 写 domain_configs 表
   ├── 写 origin_groups + origins
   ├── 域名状态：待审核
   └── 发事件 DomainCreatedEvent
3. 管理员审核通过
   ├── 状态 → 部署中
   ├── 自建：NodePushService.push(domainId) 推送配置到节点
   ├── 厂商：driver.deploy(domainId)
   ├── 生成 DNS CNAME 引导
   └── 状态 → 已启用
4. 用户配置 CNAME
5. DomainService.checkCname() 验证
6. 域名生效
```

5.2 配置变更推送

```
1. 用户修改缓存规则
2. CacheRuleService.update()
   ├── 写 DB
   ├── 发事件 ConfigChangedEvent(domainId)
3. NodePushService 监听事件
   ├── 查域名归属节点组
   ├── 生成配置 diff
   ├── 入队 node-push 任务
4. NodePushProcessor 消费
   ├── 遍历节点
   ├── HTTP POST https://node/config/push
   ├── 带 X-Node-Token + 签名
   ├── 成功 → 记录 node_configs
   └── 失败 → 重试（最多 3 次）
5. 节点接收 → 写配置 → reload
```

5.3 刷新预热

```
1. 用户提交刷新
2. PurgeService.create()
   ├── 校验配额
   ├── 写 purge_tasks
   ├── 入队 purge 任务
3. PurgeProcessor 消费
   ├── 自建：调所有相关节点
   │   ├── HTTP POST https://node/command
   │   ├── body: { command: 'purge', urls: [...] }
   │   └── 节点执行 → 清缓存
   ├── 厂商：调 driver.purge()
   ├── 汇总结果
   └── 更新 purge_tasks + purge_records
4. 用户查询进度
```

5.4 流量统计聚合

```
1. 节点每 5 分钟上报流量
2. TrafficService.record()
   ├── 写 traffic_usage（原始）
   └── 更新 user_packages.traffic_used
3. StatisticsScheduler 每小时跑
   ├── 聚合 traffic_usage → traffic_stats_hourly
   ├── 聚合 region_stats、status_code_stats、top_url_stats
   └── 入队 daily 任务
4. 每日凌晨聚合 → traffic_stats_daily
5. 用户查询统计 → 查聚合表
```

5.5 套餐过期与配额

```
1. PackageExpireScheduler 每天跑
   ├── 查 user_packages 过期
   ├── 状态 → 过期
   ├── 用户 package_id 置空
   ├── 发送通知
   └── 域名停用（可选）
2. TrafficService.checkQuota()
   ├── 每次记录流量后检查
   ├── 超配额 → 按 over_quota_policy
   │   ├── 限速：推送到节点
   │   ├── 按量扣费：扣余额
   │   └── 停服：域名停用
   └── 发告警
```

5.6 证书自动续期

```
1. CertRenewScheduler 每天跑
   ├── 查 30 天内到期证书
   ├── 入队 cert-renew 任务
2. CertRenewProcessor 消费
   ├── 调 ACME 申请新证书
   ├── 更新 certificates
   ├── 推送到节点
   └── 发通知
```

5.7 节点健康检查

```
1. NodeHealthScheduler 每 30 秒跑
   ├── 遍历在线节点
   ├── HTTP POST https://node/health
   ├── 超时/失败 → 记录
   ├── 连续失败 3 次 → 标记离线
   ├── 触发 FailoverService
   │   ├── 从负载均衡中剔除
   │   ├── 更新 DNS 解析
   │   └── 发告警
   └── 恢复 → 重新加入
```

7.2 驱动工厂

```ts
@Injectable()
export class DriverFactory {
  constructor(
    private aliDriver: AliDriver,
    private tencentDriver: TencentDriver,
    private cloudflareDriver: CloudflareDriver,
    private awsDriver: AwsDriver,
  ) {}

  getDriver(code: string): VendorDriver {
    switch (code) {
      case 'ali': return this.aliDriver
      case 'tencent': return this.tencentDriver
      case 'cloudflare': return this.cloudflareDriver
      case 'aws': return this.awsDriver
      default: throw new Error(`Unknown vendor: ${code}`)
    }
  }
}
```

19. 代码规范

19.1 命名

类型 规范 示例
模块 PascalCase + Module DomainModule
服务 PascalCase + Service DomainService
控制器 PascalCase + Controller DomainController
DTO PascalCase + Dto CreateDomainDto
实体 PascalCase Domain
守卫 PascalCase + Guard JwtAuthGuard
拦截器 PascalCase + Interceptor TransformInterceptor
装饰器 camelCase currentUser
常量 UPPER_SNAKE MAX_PAGE_SIZE

19.2 分层

```
Controller → Service → Repository → Prisma
```

· Controller：路由、参数校验、权限
· Service：业务逻辑
· Repository：数据访问（可选，简单场景直接用 Prisma）

19.3 DTO 校验

```ts
export class CreateDomainDto {
  @IsString()
  @Matches(/^([a-z0-9-]+\.)+[a-z]{2,}$/i)
  domain: string

  @IsOptional()
  @IsString()
  @MaxLength(255)
  remark?: string
}
```

19.4 事务

await this.prisma.$transaction(async (tx) => {
