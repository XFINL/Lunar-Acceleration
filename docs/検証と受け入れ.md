# 検証とクラウド接続の受け入れ

ローカルの自動テスト成功と、実際の CDN が安全に稼働することは別の確認です。登録、設定配信、読み取り専用同期を区別し、リモート状態だけでローカルドメインを有効化しません。

## ローカル検証

Node.js 20 以上、pnpm 10、MySQL 8、Redis 7、OpenSSL が必要です。設定例は `apps/server/.env.example` にあります。秘密値はコミットしないでください。

名前が `_test` で終わる専用データベースを作成し、接続先を設定して実行します。このコマンドはマイグレーション、初期データ、テスト用レコードを作成するため、本番データベースを指定してはいけません。

```sh
export DATABASE_URL='mysql://USER:PASSWORD@127.0.0.1:3306/lunar_test?connection_limit=5'
export REDIS_HOST=127.0.0.1
export REDIS_PORT=6379
node scripts/verify.mjs
```

検証はロックファイル固定インストール、Prisma 生成、マイグレーションと初期データの反復実行、ESLint、型検査、ビルド、単体・UI・DB/HTTP 統合テストを順番に実行します。データベース URL が未指定または専用テスト用でなければ停止し、DB 未指定による統合テストのスキップを合格と扱いません。統合テストのファイルは直列で実行します。検証スクリプトの安全ガード自体は次のコマンドで確認できます。

```sh
node --test scripts/verify.test.mjs
```

検証中は通常の ACME・クラウド書き込みワーカーを無効化します。書き込みの回帰テストはケース内で明示的に設定を有効化し、クラウド通信をローカルの代替実装に差し替えます。テストは実クラウドや実 CA の受け入れ確認にはなりません。

## 既存データベースの更新

更新前に必ずバックアップを取得してください。`db push` や DB リセットを本番更新手段にしません。M4 キューの SQL 順序修正は過去のマイグレーションに影響するため、[順序修正と移行履歴の注意事項](../apps/server/prisma/MIGRATION_ORDER_FIX.md)を確認してください。適用済みチェックサムを自動で書き換えたり、失敗した適用を確認せず成功扱いしたりしません。

新規インストールの専用受け入れ試験は、空のローカル DB で `apps/server/prisma/tests/migrate-deploy-acceptance.sh` を実行します。通常の統合テスト用 DB とは別の、空の DB を使用してください。

## 実クラウドの受け入れ条件

実際の認証情報と管理下のテストドメインがない環境では、この確認は実施できません。ローカル検証完了を本番接続完了と表現してはいけません。

### M4 の配信対象と制約

Cloudflare は単一の公開 HTTPS:443 のホスト名源、Aliyun は単一の公開 HTTP:80 または HTTPS:443 の源を対象とします。TTL は 1〜31,536,000 秒です。配信は所有が記録されたリソースに限り、任意のカスタムキャッシュ規則、Host 上書き、複数源、HSTS、強制 HTTPS、TLS バージョン調整は拒否します。対応を黙って省略しません。

キャッシュは新規の既定 TTL 規則を追加するか、既存の完全一致を確認します。既存の同名・ルート規則と設定が異なる場合は、過去にパネルで配信した TTL の変更も含めて競合扱いにし、自動上書きしません。Cloudflare では既存 Ruleset 全体を PUT せず単一規則追加を使います。Aliyun で回源プロトコルポリシーが有効な場合は、源のポートからプロトコルを証明できないため拒否します。公式の[回源ポリシーの優先関係](https://www.alibabacloud.com/help/en/cdn/user-guide/configure-the-origin-protocol-policy)も参照してください。

HTTPS が有効な場合は、ユーザーが所有する有効な SAN 証明書と一致する鍵を実行時だけ復号・配信し、公開証明書の SHA-256 指紋を読み戻して検証します。無効な場合に実行するのは源・キャッシュの配信だけであり、既存のベンダー TLS 設定や証明書を削除・無効化しません。API の `verifiedFeatures` を確認してください。キューに保持するのは証明書 ID と公開指紋だけで、PEM や鍵は保持しません。

複数書き込みからなる配信を開始した後のエラーは、429 や認証エラーでも「未実行」と断定せず人工確認に隔離します。読み取り結果、ローカル設定、リソースの対応付け、証明書の識別が一致した場合だけ成功を記録します。DNS やドメイン公開状態は自動変更しません。

1. 専用の最小権限アカウントとテストドメインを用意します。Cloudflare は対象 Zone と製品・契約上の機能を確認し、Aliyun は対象 CDN API だけを許可した RAM アカウントを使用します。
2. 読み取り専用の接続テストと同期を実行し、別アカウントや未知ドメインを認識・所有してしまわないことを確認します。同期が書き込みや自動有効化を行わないことも確認します。
3. 必要な書き込み権限だけを付与し、`VENDOR_WRITES_ENABLED=true` と `VENDOR_WRITE_WORKER_ENABLED=true` を明示的に設定した常駐アプリケーションで受け入れを行います。通常環境では両方とも無効です。
4. 管理画面で対象アカウント、ドメイン ID、操作を確認し、登録と設定配信を別々に実行します。未対応の設定が書き込み前に拒否されること、配信後に設定が読み戻されることを確認します。
5. ベンダー管理画面・公式 API と比較し、実際の DNS、HTTPS 接続、オリジン、キャッシュ動作を外部から確認します。API の成功や設定読み戻しだけでは通信経路全体の証明になりません。
6. タイムアウト、結果不明、ローカル保存失敗は `needs_review` として扱い、実リソースを確認するまで重複書き込みをしません。秘密鍵や認証情報がレスポンス・キュー・監査ログに出ないことを確認します。
7. パネルが作成・所有を記録したテストリソースだけを削除し、ベンダー側で削除結果を確認します。読み取り同期で見つけただけのリソースは削除対象にしません。

## 里程標の境界

元の仕様では M4 は第三者ベンダー接続、M5 は統計・レポート・ログ・リアルタイムログです。地域別の DNS 調整、負荷分散、フェイルオーバーは M7、ユーザー向け更新・プリフェッチのキューと履歴は M8 に属します。M4 で設定配信が実装されても、これらの後続機能が完成したことにはなりません。
